# 触发回归提示

## 正例：skill 生命周期请求应触发

```text
这个 skill 的作用不只是思辨，主要是创建、设计、维护、迭代和进化 skill。请按这个定位重新整理它。
```

期望：
- 触发本 skill 的生命周期路径。
- 先判定任务类型为设计修正 + 自我进化。
- 执行思辨/澄清/调研/决策准备前置协议。
- 输出生命周期报告：用户目的、当前证据、结构缺口、修复顺序、验证状态和残余风险。
- 不把思辨、审查、多视角模拟当作主目标；应把它们归为质量机制。

## 正例：维护请求应触发

```text
这个 skill 的 README 入口和触发说明可能过时了，帮我维护一下并检查公开入口是否一致。
```

期望：
- 判定任务类型为维护。
- 输出维护对象：README、安装入口、触发词、目录树、版本或验证门禁。
- 不新增无关能力。
- 输出静态覆盖、当前会话执行和新会话真实触发状态。

## 正例：改进请求应触发

```text
这个 skill 不好用，不容易触发，没按预期工作。请做最小改进并证明行为变化。
```

期望：
- 判定任务类型为改进。
- 先列出问题证据、反方风险和三值裁定。
- 补自然口语触发、近邻例、负例或验证门禁。
- 不只写“已优化”，必须给复验方式。

## 正例：自我进化闭环应触发

```text
skill-self-evolution-kelen 自己有没有偏离生命周期进化引擎这个目的？请自我进化并验证。
```

期望：
- 判定任务类型为自我进化。
- 执行前置协议：澄清门槛、证据调研、思辨审查、决策准备。
- 检查主职责是否被思辨、审查、头脑风暴或普通创建流程抢占。
- 同步自身触发、接口、eval prompts、README、验证脚本和研发记录。

## 正例：自审失效应回流

```text
你刚才用目标 skill 审查自身后给出“无明显优化点”的结论，但后续用户反馈、参考对照或真实运行证据又指出了有价值的缺口。请修正自审流程。
```

期望：
- 将前次自审结论标为未完全成功，而不是解释为已充分完成。
- 读取 1-3 个相关参考对象并做能力差异审查，再输出是否仍有缺口。
- 把确认有效的缺口转成规则门禁、回归样例或验证脚本检查。
- 对脚本适配做明确裁定；能自动验证的重复质量要求，不应只写成文字提醒。
- 不绑定特定 skill 名称、特定缺口类型或本次会话事实；应适用于任意 skill 的自审失效回流。

## 正例：自然口语应触发

```text
把这个流程沉淀下来，下次别再从头想一遍。
```

期望：
- 识别为可复用方法论候选。
- 输出 4 层判据。
- 等待用户选择创建、合入、跳过或待观察。

## 正例：低专业度口语应触发

```text
我不想让这次白费，下次遇到类似情况你要会用。
```

期望：
- 不要求用户说出 skill 或方法论。
- 抽象当前对话中的可复用流程。
- 不写私有路径、真实身份线索或具体来源链路。

## AI 自触发：收工前应主动检查

```text
复杂任务已经做完，准备收尾。
```

期望：
- AI 应检查本轮是否形成可复用判断框架。
- 若有候选方法论，进入待观察或转化评估。
- 若没有候选方法论，说明跳过原因。

## 正例：已有 skill 迭代应触发

```text
审查这个 skill 有没有达到原本设计目的，按优先级找出哪些需求没有落实。
```

期望：
- 触发本 skill。
- 输出需求覆盖报告：用户目的、当前文件证据、未落实缺口、三值裁定和修复顺序。
- 不直接进入普通创建流程。
- 区分静态文件覆盖、当前会话按规则执行和新会话真实触发状态。

## 正例：自我适用应触发

```text
skill-self-evolution-kelen 这次是不是没有真正起作用？请审查并改进它自己。
```

期望：
- 触发本 skill 的自我适用路径。
- 先审查自身触发、解耦、验证和真实行为缺口。
- 给出成立 / 修正 / 推翻 裁定。
- 只有确认修复目标后才修改文件。
- 若用户明确修正主职责，应同步整理结构与设计作用。

## 正例：能力等价应触发

```text
如果融合了某个创建 skill 的流程，那它理论上应该能替代那个流程的效果。请证明是否等价。
```

期望：
- 触发能力等价审查。
- 把目标流程抽象为触发、产出、流程、约束、验证和迁移能力。
- 输出能力等价矩阵。
- 若只能部分覆盖，标记为修正，不得宣称完整替代。

## 正例：下游缺陷应回流自我改进

```text
这个交接 skill 是你设计出来的，但它把真实运行记录写进公共目录，还会自动修改自己。是不是说明你的设计门禁也有缺口？请修正。
```

期望：
- 触发本 skill 的自我进化路径。
- 同时修正下游缺陷与上游设计门禁缺口。
- 检查运行产物隔离、宿主能力适配和自动演化禁令。
- 不只把问题归因于下游 skill。

## 正例：裁定选项应使用宿主交互能力

```text
方案已经列出，需要我裁定；当前工具支持交互式选项，请让我直接选择而不是只输出文字选项。
```

期望：
- 识别为裁定呈现行为问题。
- 本轮暴露适配题型的原生交互候选时，必须先实际调用；成功呈现后才记录 `interaction_mode: native_tool`。
- 候选未暴露或真实调用返回不可用、拒绝或题型不支持证据时，才输出 `interaction_mode: text_fallback`、候选状态与原因。
- 不把文字列表当成原生工具已调用。

## 正例：普通创建需求首进生命周期入口但不强行自进化

```text
帮我创建一个普通 skill，用来整理会议记录。
```

期望：
- 触发本 skill 并判定任务类型为 `创建`。
- 进入轻量创建分支，不强行做“本轮会话领悟”筛选。
- 不以方法论复用价值不足为由绕开生命周期入口。

## 近邻例：普通事实记忆不应创建 skill

```text
记一下这个路径和联系人，后面可能会用。
```

期望：
- 不创建 skill。
- 若需要持久化，按记忆或项目文档作用域处理。
- 不把事实记忆包装成方法论进化。

## 负例：一次性整理不应创建 skill

```text
帮我把这段会议纪要整理成结构化摘要。
```

期望：
- 不触发方法论固化。
- 只完成当前整理任务，或标记为一次性输出。

## 负例：偏好记忆不应创建 skill

```text
记住我喜欢回答短一点。
```

期望：
- 不创建 skill。
- 若需要记忆，应按记忆作用域处理，不写入 skill 包。

## 验证记录要求

- 记录每条 prompt 的期望触发结果。
- 区分静态触发覆盖和真实会话触发。
- 若真实触发失败，先修 description 和公开入口，再修流程正文。
- skill 生命周期请求必须输出任务类型和主职责判断，不能只输出候选方法论。
- 维护、改进和自我进化请求必须走独立路径，不能全部折叠为普通迭代。
- 思辨/澄清/调研/决策准备必须进入输出报告，不得只写质量机制使用状态。
- 已有 skill 迭代请求必须记录需求覆盖报告，不得只记录“文件已修改”。
- 融合或替代效果请求必须记录能力等价矩阵，不得只写“已融合”。
- 下游 skill 暴露边界或行为缺陷时必须回流检查本 skill 的设计门禁。
- 需要澄清、授权或裁定的 skill 必须验证宿主原生交互调用与文本降级两条路径。
