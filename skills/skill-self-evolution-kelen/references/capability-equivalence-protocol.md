# 能力等价协议

## 目标

当用户要求“融合”“借鉴”“吸收”“替代某流程效果”时，不能只写参考说明或概念摘要。必须证明目标能力已被当前 skill 的触发、流程、输出、验证和边界覆盖。

## 等价对象抽象

不要在 skill 执行规则中写入来源名、私有路径或研发灵感。先把目标能力抽象为能力项：
- 触发能力：什么用户话术或 AI 自我判断会启动它。
- 产出能力：它必须输出什么结果。
- 流程能力：它如何从输入走到输出。
- 约束能力：它必须避免什么风险。
- 验证能力：如何证明结果有效。
- 迁移能力：换到另一个运行时或项目后是否仍成立。

## 三值裁定

对每个能力项给出裁定：
- 成立：当前 skill 已有触发、流程、输出和验证证据，能覆盖该能力。
- 修正：方向可覆盖，但缺少触发、流程、输出、边界或验证中的一项。
- 推翻：该能力与当前 skill 目标冲突，或需要独立 skill 承担。

`待确认` 只能表示证据状态，不是第四种裁定。

## 覆盖矩阵

以下为模板，<...> 标记需替换为实际内容。

```markdown
### 能力等价矩阵
- 目标能力：<抽象能力项>
- 来源效果：<只写抽象效果，不写来源名或私有路径>
- 当前覆盖：<触发 / 流程 / 输出 / 验证 / 边界>
- 裁定：<成立 / 修正 / 推翻>
- 缺口：<没有则写“无”>
- 修复：<最小修复动作>
- 复验：<正例 / 近邻例 / 负例 / 新会话真实触发>
```

## 验证要求

- 至少覆盖正例、近邻例和负例。
- 若目标能力声称可替代某流程，必须给出“替代前后”的行为对照。
- 若只能覆盖部分能力，必须明确写“部分等价”，不得写成完整替代。
- 若真实新会话未验证，必须写“新会话真实触发未验证”。
- 若能力来自外部资料或用户灵感，skill 文件只保留抽象能力；来源记录放到研发文档。

## 失败信号

- 只写“融合了某方法”，没有能力项。
- 只改 description，没有输出或验证变化。
- 只跑静态检查，没有正例/近邻例/负例。
- 仍需要回到被替代流程才能完成核心任务。
- 用户自然口语命中相同任务时，实际路由仍被其他流程抢占。
