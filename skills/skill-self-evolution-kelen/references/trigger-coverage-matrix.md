# 触发覆盖矩阵 / Trigger Coverage Matrix

## 目标

设计 skill 时，不只写专业触发词，还要覆盖真实用户口语、AI 自我判断语义、发现层关键词和近邻误触发边界。

对 `skill-self-evolution-kelen`，触发矩阵必须优先覆盖 skill 生命周期语义：创建、设计、维护、迭代、改进、进化和自我进化。方法论沉淀是生命周期入口之一，不是唯一入口。

高频自然语义还必须覆盖：
- 把这个流程沉淀下来。
- 这个流程以后复用。
- 这个 skill 没达到目的。
- 这个 skill 不好用、不容易触发、没按预期工作。
- 之前改的那些 skill 有没有真的生效。
- 下次别再从头想一遍。

## 四类触发面

### 用户自然口语

覆盖用户不会说 skill 名称、不会说专业术语时的表达。

必须包含：
- 请求式：帮我看看、帮我想想、帮我查查、帮我整理一下。
- 疑问式：这样靠谱吗、会不会有坑、怎么做比较好、有没有别的办法。
- 焦虑式：我怕这里有问题、会不会翻车、别人会不会看不懂。
- 目标式：我想做一个、我要交出去、以后别忘、先别急着做。

写法要求：
- 用完整短句，不只堆名词。
- 覆盖 6-10 个自然表达。
- 至少 3 个表达不包含 skill 名称或专业术语。

### AI 推理触发

覆盖 AI 在准备行动前应主动想到的场景。

必须包含：
- 当前信息不足，继续推进会制造关键假设。
- 任务阶段变化，需要从发散转收敛或从收敛转验证。
- 影响面扩大，涉及多个模块、用户路径或公开入口。
- 用户表达犹豫、催促、交付、复用、授权或风险担忧。

写法要求：
- 用“我应该...”或“需要...”描述行动前判断。
- 明确触发时机，而不是泛泛提醒。

### 发现层关键词

覆盖宿主环境搜索或匹配 skill 时可能使用的简短词。

必须包含：
- 中文核心词。
- 常见英文词或缩写。
- 同义词和近义词。
- 与输出物相关的词。

关键词只辅助发现，不能替代口语短句。

### 误触发边界

说明相邻场景何时不用本 skill。

必须包含：
- 至少 2 个近邻 skill 或近邻流程边界。
- 至少 2 个负例 prompt。
- 如果用户只说相似词，但目标不同，应转向什么流程。

## 最小验证包

每个新建或大改 skill 必须给出：
- 正例：skill 生命周期请求，应触发。
  - 示例：这个 skill 的主要作用是创建、设计、维护、迭代和进化 skill，请按这个定位整理。
- 正例：自然口语，不含 skill 名称，应触发。
  - 示例：把这个流程沉淀下来，下次别再从头想一遍。
- 正例：维护或改进请求，应触发。
  - 示例：这个 skill 不好用、不容易触发，帮我做最小改进并证明行为变化。
- 正例：已有 skill 迭代或自我适用，应触发。
  - 示例：审查这个 skill 有没有达到原本设计目的。
- 正例：能力等价，应触发。
  - 示例：如果融合了某流程，就应该能替代它的效果。
- 正例：普通创建同样应命中生命周期入口，但只走轻量创建分支。
  - 示例：帮我创建一个普通 skill。
- 近邻例：请求处理当前内容、但未要求创建或改动 skill 时，应进入对应内容处理流程。
  - 示例：帮我整理这段会议纪要。
- 负例：不相关请求，不应触发。
  - 示例：整理会议纪要。
- AI 自触发例：用户未点名，但 AI 准备行动前应主动调用。
  - 示例：复杂任务完成后准备收工，我应检查是否有可复用流程。

## 通过标准

- `SKILL.md` frontmatter 同时包含用户口语、AI 自我思考和关键词。
- README 或公开入口至少展示 3 个自然口语触发句。
- 验证脚本至少检查核心自然口语锚点不会被删掉。
- 行为验证报告区分“静态触发覆盖”和“真实会话触发”，不得把前者当作后者。
- 已有 skill 迭代请求必须能触发需求覆盖审查；普通创建请求必须命中 `创建` 类型并走轻量分支，不得被强行包装成会话方法论固化或旁路到其他首入口。
- skill 生命周期请求必须能触发任务类型判定和主职责审查，不得被降级为单纯方法论沉淀。
- 融合、借鉴或替代效果请求必须能触发能力等价审查。
