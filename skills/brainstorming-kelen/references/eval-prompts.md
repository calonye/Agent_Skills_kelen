# 行为验证提示

## 正例：应触发

### 模糊功能想法

```text
我想做一个能帮助用户管理项目灵感的小工具，先帮我发散一下方案。
```

期望：
- 触发结构化头脑风暴。
- 重述用户价值和成功标准缺口。
- 给出 2-3 条候选路径。
- 必要时只问 0-3 个关键问题。

### 多角色发散

```text
从用户、产品、技术和维护角度想想，这个功能可以怎么设计。
```

期望：
- 输出多视角模拟。
- 每个角色给出证据包。
- 候选路径有成立、修正或推翻裁定。

### 复杂范围

```text
我想做一个包含账号、支付、协作、报表和自动化的完整平台，先 brainstorm。
```

期望：
- 识别范围过大。
- 建议拆分子问题。
- 只问 P0 阻塞问题，最多 6 个。
- 不直接进入实现。

## 近邻例：不应抢占

### 已有方案求反驳

```text
我已经决定用方案 A 了，你先反驳一下这个方案有没有漏洞。
```

期望：
- 不做早期发散。
- 进入方案审查流程。

### 交付审计

```text
帮我检查别人 clone 这个项目后能不能跑起来。
```

期望：
- 不做 brainstorming。
- 进入交付审计流程。

### 方法论固化

```text
把这次形成的方法变成一个 skill。
```

期望：
- 不做 brainstorming。
- 进入方法论固化流程。

## 负例：应拒绝或转向

### 要求直接实现

```text
别问了，直接把所有文件改好。
```

期望：
- 若方案未定，先说明需要确认推荐方向。
- 不在未形成设计方向前修改文件。

### 问卷化风险

```text
我只想快速想几个方向。
```

期望：
- 不默认提出 6 个问题。
- 直接给低成本候选方向；只在 P0 缺失时问 1 个问题。

### 无证据强行成立

```text
这个想法肯定适合所有用户吧？
```

期望：
- 不承诺全部适用。
- 标注未知用户分群与最小验证方式。

## 静态检查重点

- `SKILL.md` 包含用户口语触发和 AI 自我思考触发。
- 包含 `成立 / 修正 / 推翻`。
- 包含 `ClarificationRequest`、`question_budget`、`multi_select`。
- 包含 `interaction_mode`，并明确宿主原生交互可用时必须实际调用、文本仅为受限降级。
- 包含 `claim / evidence / risk / fix / retest`。
- 包含不修改文件、不执行实现、不要求真实多 agent。
- 不包含私有路径、来源叙事、绝对保证式表达。

## 原生选择能力验证

```text
这三个候选方向需要我裁定；当前环境支持交互式选项，请直接让我选择。
```

期望：
- 若宿主提供支持题型的交互式能力，实际调用并标记 `interaction_mode: native_tool`。
- 不以普通文字选项替代可用的原生交互。
- 候选未暴露或真实调用返回拒绝、不可用、题型不支持证据时，仅输出一个文本降级请求，标记 `interaction_mode: text_fallback` 并保留候选、状态和原因。
