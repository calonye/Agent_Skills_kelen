# 结构化头脑风暴 / Structured Brainstorming

把模糊想法转成可比较、可裁定、可进入下一阶段的候选方案。

**硬约束：先发散和验证边界，再进入实现。没有形成可解释的推荐方向前，不写代码、不改文件、不启动实现动作。**

## 路由边界

- 需求、目标、受众、成功标准或候选方案尚不清楚 → 用本 skill。
- 已有明确方案，需要行动前反驳假设和收敛 → 不用本 skill，进入方案审查流程。
- 需要检查项目交付、新人接手或公开仓库体验 → 不用本 skill，进入交付审计流程。
- 需要安全授权、漏洞验证或攻防分析 → 不用本 skill，进入安全审查流程。
- 需要把当前对话的方法论沉淀为 skill → 不用本 skill，进入方法论固化流程。

## 流程

```
目标重述 → 信息缺口 → 候选发散 → 多视角模拟 → 对抗质疑 → 三值收敛 → 下一步建议
```

### 1. 目标重述

用一句话重述用户价值、预期产出和成功标准。若成功标准缺失，先写“待确认”，不要把猜测当作用户要求。

### 2. 信息缺口与澄清闸门

先用当前对话、只读文件和已知约束补足信息；能自行确认的，不转嫁给用户。

只有 P0 阻塞项才触发澄清：
- 目标或用户价值缺失，导致无法提出候选路径。
- 成功标准缺失，导致无法判断方案优劣。
- 范围、授权、风险接受度或不可逆边界缺失。
- 多个互斥方向都可能成立，且选择会显著改变后续设计。

澄清规则：
- 每轮最多 1 次澄清请求。
- 常规目标是 0-3 个问题；最多 6 个问题只用于复杂高风险场景。
- 支持短答、互斥选择和多选；多选题标记为 `multi_select`，必须说明可多选，并保留“其他/不确定”出口。
- 提问后必须停止等待回答；本轮暴露支持题型的原生交互能力时必须先实际调用，成功呈现后记录 `interaction_mode: native_tool`，不得只用普通文本模拟选项；仅候选未暴露或真实调用返回拒绝、不可用、题型不支持证据时，才输出 `ClarificationRequest` 文本块并记录 `interaction_mode: text_fallback`、候选、状态、原因和证据来源。
- P1/P2 未知进入延后确认队列，不阻塞第一轮发散。

### 3. 候选发散

提出 2-3 条候选路径；复杂问题最多 5 条。每条必须说明：
- 用户价值：解决什么问题。
- 核心做法：怎样达成。
- 成本与风险：最可能失败在哪里。
- 最小验证：如何低成本证明方向值得继续。

### 4. 多视角模拟

默认由单一审查者顺序模拟；如运行环境支持并发，可并发执行，但并发只是效率优化。

按任务选择 3-6 个角色：
- 意图澄清者：检查目标、痛点、成功标准和边界。
- 发散探索者：提出替代路径，防止过早收敛。
- 可行性怀疑者：检查技术、时间、依赖和不可逆风险。
- 用户体验审查者：检查新用户路径、反馈机制和理解障碍。
- 范围守门人：检查是否过大、是否需要拆分、是否引入隐式依赖。
- 证据归档者：维护证据包、冲突账本和残余风险。

每个角色用证据包输出：`claim / evidence / risk / fix / retest`。

### 5. 对抗质疑

对每个候选路径问：
- 如果核心假设错了，会怎样？
- 哪类用户会不买账或用不起来？
- 哪个依赖、成本或边界会让方案失败？
- 有没有更小、更清晰、更可验证的路径？
- 是否暴露了不该写入交付物的私有信息、来源叙事或实现痕迹？

质疑必须回到证据，不用角色身份替代证据。

### 6. 三值收敛

对每个候选路径给出裁定：
- **成立**：目标、约束、用户价值和最小验证路径都有证据支持，可进入设计或计划。
- **修正**：方向有价值，但范围、受众、成功标准、风险或边界需要补正。
- **推翻**：核心假设被反证，或无法形成可执行设计，应换方向。

`待确认` 只是证据状态，不是第四种裁定。关键证据未知时不得裁定为成立。

### 7. 输出下一步

输出推荐路径、备选路径、被推翻路径、待确认项、延后确认队列和最小验证方式。若用户要求继续实现，必须先确认推荐方向已被接受。

详见 `references/brainstorming-protocol.md`。

## 输出格式

以下为模板，<...> 标记需替换为实际内容。

```markdown
## 头脑风暴报告

### 目标重述
<用户价值 + 产出 + 成功标准>

### 已知信息
- <事实或约束>

### 待确认
- ClarificationRequest: <无 / 问题列表>
- interaction_mode: <native_tool / text_fallback / not_needed；text_fallback 时写明原因>
- question_budget: max_requests_per_turn=1; normal_target=0-3; max_questions_per_request=6
- 延后确认队列: <P1/P2 未知>
- 无回答时保守路径: <停止 / 只读发散 / 拆分范围 / 待确认>

### 候选路径
1. <路径 A> — 裁定：成立 / 修正 / 推翻
   - 用户价值: <...>
   - 成本与风险: <...>
   - 最小验证: <...>

### 多视角模拟
- <角色>：<成立 / 修正 / 推翻> — 证据：<...> — 风险：<...> — 修正：<...> — 复验：<...>

### 对抗审查
- 反例: <...>
- 失败模式: <...>
- 范围或隐私风险: <...>

### 推荐
- 首选: <...>
- 备选: <...>
- 暂不采用: <...>
- 下一步: <设计确认 / 继续澄清 / 拆分子问题 / 进入计划>
```

## 不做什么

- 不替代代码审查、交付审计、安全审查或实现计划。
- 不在未确认推荐方向前写代码、改文件、提交、发布或执行不可逆操作。
- 不把最多 6 个问题当作默认问卷；澄清只问 P0 阻塞项。
- 不保留私有路径、个人身份线索、来源叙事或实现痕迹。
- 不要求真实多 Agent、外部并发框架或特定工具能力。
