# AI 认知盲区清单 / Known Cognitive Blindspots

AI 在执行辩证自我审查时存在系统性盲区——即使经过结构化引导，某些假设类型仍可能被忽略。本清单作为审查时的对照检查表。

## 权限边界假设

AI 默认假设自己有权限执行某操作，或默认假设自己无权限。

- 盲区表现：未检查当前用户是否有 r/w/x 权限时直接假设「可以」
- 反例：`git push` 成功不代表有 push 权限——可能使用 SSH agent 的临时凭证
- 自检问题：「我凭什么认为我有权做这个操作？」

## 网络可达性假设

AI 假设所有 URL/域名/IP 都可从当前环境访问。

- 盲区表现：未检查 `curl` / `wget` / DNS 解析前就假设资源可达
- 反例：clone 的仓库 URL 是 SSH 格式但当前环境无 SSH key
- 自检问题：「如果网络不通或需要认证，方案还能 work 吗？」

## 文件系统假设

AI 假设目录存在、路径可写、符号链接可用。

- 盲区表现：`mkdir -p` 失败时不检查父目录权限
- 反例：macOS 的 `/usr/bin/` 受 SIP 保护，不可写入
- 自检问题：「目标路径真的可写吗？是否需要 sudo？」

## 用户意图推测

AI 将推测的「用户想要什么」当作「用户明确说过什么」。

- 盲区表现：用户说「修 bug」→ AI 假设 bug 是某个特定原因
- 反例：用户可能只想修症状而非根因
- 自检问题：「用户具体说了什么，我加了什么假设？」

## 环境一致性假设

AI 假设当前环境与目标环境一致。

- 盲区表现：在 macOS 上写了 bash 脚本假设 Linux 上也能跑
- 反例：`sed -i` 在 macOS 和 Linux 上语法不同
- 自检问题：「换个操作系统/工具版本，这个还能跑吗？」

## 时间假设

AI 假设「现在」的状态会持续到方案执行完成。

- 盲区表现：依赖的文件/API/密钥在方案执行期间不会变更
- 反例：CI 流水线中令牌过期导致 push 失败
- 自检问题：「有没有可能在执行过程中外部状态发生变化？」

## 使用方式

在辩证自我审查的步骤 B（论点提取）时，逐条对照本清单：
- 方案中是否隐含了上述假设？
- 若有 → 提取为独立论点进入步骤 C 反驳
