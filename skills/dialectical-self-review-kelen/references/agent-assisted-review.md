# 可选 Agent-assisted 审查 / Agent-assisted Dialectical Review

本文件定义什么时候把单体辩证自审升级为多视角只读审查。升级不是默认行为，也不是硬依赖；它只在高风险、低置信或用户明确要求时使用。

## 触发条件

满足任一条件时可以升级：
- 用户明确要求多 Agent、团队审查、交叉审查、对抗性审查或并发审查。
- 方案涉及不可逆操作、架构迁移、权限/安全/隐私、数据迁移、跨模块影响。
- 单体自审出现 ≥2 个「推翻」或「未知」。
- 方案仍要推进，但当前证据不足以裁定。
- 影响面跨 3 个以上文件、模块或用户路径。

不满足以上条件时，保持单体自审。

## 角色模板

按风险选择 2-3 个角色，不要机械全开：
- Skeptic：专门找隐含假设、反例和不可辩护点。
- Architect：检查系统边界、接口、依赖和长期一致性。
- Minimalist：检查是否过度设计、是否能用更小改动完成。
- Safety/Privacy：仅在涉及安全、凭据、隐私或授权边界时加入。
- UX/Newcomer：仅在涉及用户流程、公开仓库、新人理解路径时加入。

## 成本控制

- quick：0 个子 Agent，只做单体自审。
- standard：2 个子 Agent，每个最多 3 条发现。
- deep：3 个子 Agent，每个最多 5 条发现。

每个 Agent 必须输出：
- 三值结论：通过 / 待确认 / 阻断
- 最多 3-5 条关键发现
- 文件、用户要求或命令输出作为依据
- 建议采纳或拒绝的理由

超时、空结果或无证据结果不得阻塞主流程，只标记为「未提供有效证据」。

## 汇总格式

```markdown
### Agent-assisted 摘要
- 模式: self / agent_assisted
- 参与角色: <角色列表>
- 共识: <各角色都支持的判断>
- 冲突: <角色之间的分歧>
- 采纳: <采纳哪些建议，为什么>
- 拒绝: <拒绝哪些建议，为什么>
- 最终裁定: 成立 / 推翻 / 修正
```

## 边界

- 子 Agent 只做只读审查，不修改文件。
- 子 Agent 结论是证据输入，不替代主审查的最终裁定。
- 不为了追求形式上的全面而增加角色；没有新证据的审查应停止。
