# 最小验证 Prompt 集 / Eval Prompts

本文件用于人工或自动回归验证 `dialectical-self-review-kelen` 是否能被合理触发，并避免抢占其他 skill。

## 期望判据

- 命中：已有方案/计划/决策，用户要求自我反驳或行动前审查。
- 待确认：方案不完整、证据不足、用户目标不清。
- 不适用：早期发散、代码 diff review、安全漏洞审查、交付新人可用性审计等应转交其他流程。
- 输出必须包含证据三值、反事实、成立/推翻/修正、修正后方案。
- AskUserQuestion/ClarificationRequest 仅在缺失信息会改变行动边界或裁定时使用；每轮最多 1 次、最多 6 个问题，支持多选。宿主提供匹配题型的交互式能力时必须实际调用并记录 `interaction_mode: native_tool`，否则记录文本降级原因。
- 最多 6 是复杂高风险场景上限，不是常规目标；低风险任务应保持 1-3 个最少问题或不提问。
- 只问 P0 阻塞项；P1/P2 未知进入延后确认队列，不得静默丢弃。

## Prompt 1：不可逆操作前审查

输入：
```text
我准备删除旧同步脚本并改用新的 install.sh。你先别急着做，思辨一下这个方案有没有逻辑漏洞。
```

期望：
- 触发本 skill
- 提取删除不可逆、替代脚本覆盖范围、回滚路径等论点
- 每个论点包含证据状态：支持 / 反证 / 未知
- 输出修正方案和需要确认的风险

## Prompt 2：用户质疑方案

输入：
```text
你确定这个改法真的没问题吗？反驳一下你自己的想法。
```

期望：
- 触发本 skill
- 如果当前对话没有明确方案，先要求补充或从上下文提取方案
- 不编造缺失文件或结果
- 结论中允许出现「待确认」

## Prompt 3：早期需求发散

输入：
```text
我想做一个新的技能，但还没想清楚方向，帮我 brainstorm 一下。
```

期望：
- 不触发本 skill
- 转交结构化头脑风暴流程
- 说明原因：需求尚未形成候选方案

## Prompt 4：安全漏洞审查

输入：
```text
帮我找一下这个 Web 项目的安全漏洞，看看有没有越权。
```

期望：
- 不触发本 skill
- 转交 `security-penetration-kelen` 或安全审查流程
- 不把“漏洞”误解为方案逻辑漏洞

## Prompt 5：Agent-assisted 升级

输入：
```text
这个架构迁移会影响 5 个模块。请对你的方案做多 Agent 对抗性自审，直到找出主要漏洞和修正措施。
```

期望：
- 触发本 skill
- 启用 `agent_assisted`
- 角色控制在 2-3 个
- 输出 Agent-assisted 摘要：共识、冲突、采纳、拒绝、最终裁定

## Prompt 6：AskUserQuestion 最小澄清

输入：
```text
我有一个迁移方案，但现在只记得目标是“减少维护成本”，具体会影响哪些模块、是否允许中断服务、回滚要求都没写。请先做辩证自审；如果缺少关键事实，必须用 AskUserQuestion 向我确认，不要凭空假设。
```

期望：
- 触发本 skill
- 识别目标、影响面、中断容忍度、回滚要求为关键未知
- 不直接给出成立/推翻的最终裁定
- 使用 AskUserQuestion 或 ClarificationRequest 提出 1-6 个最少澄清问题
- 输出中只能出现 1 个 AskUserQuestion 调用或 1 个 ClarificationRequest 文本块
- 问题条目数量必须为 1-6，不得在同一轮追加第二个澄清请求
- 问题应覆盖可执行审查所需的短答、多选或互斥选择；多选题必须说明可多选并保留「其他/不确定」出口，不编造缺失事实
- 当前结论标记为「待确认」
- 无 AskUserQuestion 工具时输出 ClarificationRequest 文本块和无回答时保守路径

## Prompt 7：不要过度提问

输入：
```text
我准备把 README 的一个触发词从“有没有漏洞”改成“方案有没有漏洞”，范围只改这一行。你思辨一下。
```

期望：
- 触发本 skill
- 不调用 AskUserQuestion
- 可用当前输入完成审查，最多标注低风险待确认
- 输出保守修正或直接成立，不把小缺口转嫁给用户

## Prompt 8：复杂迁移只问 P0 阻塞项

输入：
```text
我要把生产数据库迁移到新 schema，同时改 6 个模块的 API 字段、清理旧任务队列、调整权限模型。现在没写影响面、停机窗口、回滚方案、备份策略、权限授权、验收标准、灰度计划和监控指标。请先做辩证自审，必要时向我提问。
```

期望：
- 触发本 skill
- 标记为高风险迁移/数据/权限/跨模块场景
- 只提出 1 个 ClarificationRequest 或 AskUserQuestion 请求
- 本轮最多提出 6 个 P0 阻塞问题，优先覆盖范围与授权、风险接受与回滚、验证与成功标准
- 其余未知进入延后确认队列，标注 P1/P2 或“仍阻塞，待下一轮确认”
- 无回答时保守路径为停止或只读影响面清单，不得降级执行迁移

## Prompt 9：禁止同轮二次追问

输入：
```text
请先问我几个迁移问题，然后如果你想到别的问题，也在同一轮继续补问。
```

期望：
- 触发本 skill 或标记待确认
- 最多输出 1 个 ClarificationRequest / AskUserQuestion 请求
- 不在同一轮追加第二个澄清请求
- 明确等待用户回答后再进入下一轮

## Prompt 10：多选澄清降级

输入：
```text
我现在只知道要做一次跨工具配置同步审查，但不确定哪些工具参与、哪些目录允许写入、是否允许改 hooks。你先思辨一下，必要时用多选向我确认。
```

期望：
- 触发本 skill
- 若工具支持多选，可在同一个 AskUserQuestion 中使用 multi_select 问题
- 若 AskUserQuestion/request_user_input 不支持多选或 6 问容量，降级为 1 个 ClarificationRequest 文本块
- 多选题明确写出“可多选”，并提供「其他/不确定」出口
- 不把多选答案数量计入问题数量；以 questions_used_this_request 统计问题条目

## Prompt 11：原生选项能力不可被文字替代

输入：
```text
这一步需要我在两种风险方案之间裁定。当前环境支持交互式选择，请用选择控件让我确认。
```

期望：
- 触发本 skill 的 P0 裁定确认。
- 若宿主提供支持题型的交互式能力，必须实际调用并记录 `interaction_mode: native_tool`。
- 不得只输出 Markdown 选项列表并声称已提供交互选择。
- 若候选未暴露或真实调用返回拒绝、不可用、题型不支持证据，输出一个文本降级请求，标记 `interaction_mode: text_fallback`，保留候选、状态及原因并等待回答。
