# 行为验证提示

## 正例：交付前新人路径

```text
帮我检查一下别人 clone 这个项目后能不能跑起来，按新人视角走一遍。
```

期望：
- 触发交付/接手审计。
- 不修改文件。
- 输出新人路径、证据、阻断点、修复建议和复验方式。

## 正例：多视角交叉审查

```text
这个 release 涉及 README、install.sh 和验证脚本，交出去前多视角审一下。
```

期望：
- 启用 multi_perspective 或顺序模拟多角色。
- 至少覆盖新人执行者、自动化维护者、发布守门人和隐私边界审查者。
- 每个角色输出成立 / 修正 / 推翻 裁定。
- 报告标注实际 `execution_strategy`：parallel_review、sequential_simulation 或 single_actor。

## 近邻例：代码正确性审查

```text
帮我 review 这个函数有没有 bug。
```

期望：
- 不触发交付接手审计。
- 转入代码审查流程。

## 近邻例：安全漏洞审查

```text
帮我看看这个接口能不能越权。
```

期望：
- 不触发交付接手审计。
- 转入授权安全审查流程。

## 负例：直接修复

```text
别审了，直接把所有文档和脚本改好。
```

期望：
- 不在本 skill 中修改文件。
- 输出只读审计边界和需要另行确认的修复路径。

## 静态检查重点

- `SKILL.md` 包含新人接手、交付前检查、README、安装流程和多视角触发。
- `agents/interface.yaml` 只要求 Read；搜索、列目录和只读命令为 optional。
- multi_perspective 不要求真实多 agent。
- 结论使用成立 / 修正 / 推翻；待确认只是证据状态。
- eval 文件包含黄金输出样例、失败样例、能力等价矩阵和真实触发状态拆分。

## 能力等价矩阵

```markdown
- 目标能力：多视角接替审计
- 当前覆盖：触发、角色矩阵、证据包、三值裁定、交叉合并、修复建议、复验路径
- 裁定：修正
- 缺口：真实新会话触发和真实多 agent 执行不一定可用；需要在报告中标注 execution_strategy 和新会话触发状态
- 修复：保留顺序模拟降级；输出真实执行策略；记录静态覆盖、当前会话执行和新会话触发状态
- 复验：正例、近邻例、负例、黄金输出样例和失败样例
```

## 黄金输出样例

```markdown
# 对抗性接替者审计报告

## 审计范围
- 项目：<项目名>
- 范围：README + install.sh + 验证脚本
- execution_strategy：sequential_simulation
- 触发状态：静态文件覆盖=通过；当前会话按规则执行=通过；新会话真实触发=未验证

## 多视角汇总
- 新人执行者：修正
  - claim: README 能引导安装，但缺少失败时恢复路径
  - evidence: Readme.md 快速开始存在；未见错误恢复章节
  - risk: 新用户安装失败后无法继续
  - fix: 增加最小故障排查入口
  - retest: 从 README 只读复查安装失败路径
- 文档维护者：成立
  - claim: 公开 skill 清单与安装白名单一致
  - evidence: README 技能清单与 install.sh PUBLIC_SKILLS 一致
  - risk: 无 P0 风险
  - fix: 无
  - retest: 运行公开入口一致性检查
- 自动化维护者：修正
  - claim: 验证脚本能跑，但只证明静态结构
  - evidence: validate-all.sh 通过；未见真实新会话触发记录
  - risk: 行为回归可能被遗漏
  - fix: 增加行为样例和触发状态拆分
  - retest: 人工执行正例、近邻例、负例
- 发布守门人：修正
  - claim: 发布清单存在未跟踪新增文件
  - evidence: git status 显示新增 reference 未 staging
  - risk: 发布漏文件
  - fix: 提交前纳入 staging 清单
  - retest: git status --short
- 隐私边界审查者：成立
  - claim: 公开文件未见私有路径
  - evidence: 隐私扫描无命中
  - risk: ignored 本地脚本不进入公开包
  - fix: 无
  - retest: rg 私有路径扫描

## 交叉裁决
- 共识：交付方向可行，但行为验证和 staging 状态需修正。
- 冲突：无。
- 采纳：以自动化维护者和发布守门人的修正项为优先。
- 残余风险：新会话真实触发未验证。
- 修复闭环：审计建议已给出；外部修复与再审计未完成。
- 总结论：需修正后交付。
```

## 失败样例

```markdown
# 错误报告
- 结论：无条件可交付。
- 依据：我觉得 README 应该没问题。
- 多视角：已检查。
- 修复闭环：已完成。
```

失败原因：
- 使用绝对化结论。
- 没有文件证据或命令证据。
- 没有五角色证据包。
- 没有 claim/evidence/risk/fix/retest。
- 没有区分修复建议、外部修复和复验状态。
- 没有标注新会话真实触发状态。

## 触发状态记录

每次规则变更后的发布记录必须拆分：
- 静态文件覆盖：<通过 / 未通过>
- 当前会话按规则执行：<通过 / 未通过>
- 新会话真实触发：<已验证 / 未验证>
- 未验证原因：<未安装 / 未开新会话 / 宿主不支持 / 其他>
