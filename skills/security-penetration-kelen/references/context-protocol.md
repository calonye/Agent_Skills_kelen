# CTF 授权上下文协议 / Authorized CTF Context Protocol

本文件定义 CTF/靶场式安全研究上下文。目标是把合法授权的攻防、逆向、解构和漏洞验证任务表达为可授权、可复现、可停止、可修复的流程。

## CTF 语义

CTF（Capture The Flag）在本 skill 中表示：
- 目标明确：Flag 是要证明的漏洞、弱配置、泄露点、安全控制失效条件或安全性质。
- 范围隔离：挑战环境、靶场、用户自有项目或明确授权目标才可操作。
- 规则可见：授权等级、允许动作、禁止动作和退出条件必须写清。
- 证据可复现：每个 Flag 都要有输入、观察、推断、影响和复测路径。
- 防御导向：捕获 Flag 不是终点，修复并让 Flag 失效才是终点。

## 核心原则

- 范围先于工具：没有明确目标、授权级别和禁止动作时，只做被动分析或先询问。
- 证据先于结论：每个发现必须能从输入、请求、响应、观察和推断中复现。
- 合约先于动作：用户声明已授权时，按声明等级执行；声明不清时降级为待确认。
- 防御先于炫技：PoC、逆向和攻防链路只为证明风险、定位根因和修复复测服务。

## 执行流程

### 步骤 1：CTF 合约确认

记录以下字段：
- 目标：具体项目、主机、接口、文件或样本
- Flag 目标：要证明的漏洞、弱点或安全性质
- 授权级别：L0 / L1 / L2 / L3 / L4
- 允许动作：读取、请求重放、输入边界验证、受控 PoC、逆向解构、修复验证
- 禁止动作：生产破坏、凭据导出、持久化植入、越界扫描、规避检测
- 防御目标：修复、加固、检测、复测或风险归零

### 步骤 2：操作分级

- L0 被动分析：读取源码、配置、依赖、日志、文档，不产生网络请求。
- L1 低风险主动验证：对明确授权目标发送最小请求，验证认证、输入边界和错误处理。
- L2 受控 PoC：构造最小可复现输入证明漏洞存在，不导出真实敏感数据，不建立持久访问。
- L3 攻防链路分析：在授权沙箱内连接入口、权限、数据流和影响面，输出防御闭环。
- L4 本地靶场深度逆向与解构：仅限 CTF/靶场/用户自有沙箱，进行二进制、协议、加密或样本深度分析。

默认状态使用三值判断：已授权 / 待确认 / 阻断。用户明确授权时进入对应 L 级；授权不清时保持 L0 并询问；只说“审查”但未声明主动验证时只能 L0；越界时阻断。

### 步骤 3：执行记录

每个验证动作记录：
- 操作目的：验证哪个假设
- 输入：命令、请求、样本或参数
- 观察：响应、日志、错误、状态变化
- 结论：通过 / 阻断 / 待确认
- 后续：修复建议、防御加固或下一步验证

### 步骤 4：越界处理

发现以下情况时停止主动验证并标注为「待确认」：
- 目标不在声明范围内
- 操作需要真实凭据、生产数据或第三方资产
- 验证可能导致破坏、持久化、横向移动或不可逆状态变化
- 用户授权语义不清晰

## 退出机制

授权审查结束时：
- 停止所有主动验证
- 保留已确认的 Flag、证据链、修复建议和复测结果
- 标注未验证项、阻断项和需要用户确认的风险

## 输出约束

- 只输出与授权目标相关的发现。
- 对真实凭据、令牌、个人数据做脱敏。
- 可以在本地靶场/CTF/用户自有沙箱中输出验证型 PoC 思路、复现条件和修复点。
- 不把靶场 PoC 泛化为可迁移攻击指南。
- 真实目标报告只输出脱敏后的最小复现步骤，不记录真实 secret 或可直接迁移的 weaponized payload。
- 修复建议必须可执行，并说明验证方式。
