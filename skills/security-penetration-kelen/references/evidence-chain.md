# 证据链管理 / Evidence Chain

## 原则

每个安全发现必须有一条从输入到结果的完整、独立可复现的证据链。证据链的完整性决定了一个发现是「可验证的漏洞」还是「无法确认的猜测」。

## 证据链结构

```
输入 → 请求 → 响应 → 观察 → 推断 → 结论 → 复现
```

### 第 1 层：输入（Input）
精确记录触发漏洞的最小输入。对于 Web 漏洞，包含脱敏后的 HTTP 请求方法和必要载荷。对于二进制漏洞，记录最小可复现输入字节序列。对于加密漏洞，记录参数类型、长度和错误模式；真实密钥、令牌和敏感明文必须脱敏或用占位符替代。

### 第 2 层：请求（Request）
如果输入经过了编码、加密或序列化，记录原始输入和转换后的 Wire Format。

### 第 3 层：响应（Response）
记录必要的服务端响应：HTTP 状态码、关键响应头、脱敏响应片段、响应时间、错误消息摘要。真实凭据、个人数据、生产数据和第三方数据不得进入报告。

### 第 4 层：观察（Observation）
从响应中提取异常行为：权限绕过、数据泄露、时间注入、信息泄露。

### 第 5 层：推断（Inference）
从观察到漏洞类型的逻辑推导：XSS、越权、签名漏洞。

### 第 6 层：结论（Conclusion）
最终结论附带：漏洞类型（参考 vulnerability-taxonomy.md）、CVSS 评分、触发条件。

### 第 7 层：复现（Reproduction）
提供脱敏后的最小独立复现步骤，使另一名安全研究员能在同一授权环境内复现漏洞。真实目标报告中不得输出可直接攻击第三方的 weaponized payload。

## 证据保存
- 原始请求和响应保存为 .http 文件
- 网络流量保存为 .pcap 或 .har 文件
- 截图保存为 .png，标注关键区域
- 真实凭据、令牌、个人数据和生产数据必须脱敏后再进入报告
- 若证据无法脱敏且会泄露真实 secret，记录为「证据存在但已脱敏/ withheld」，只描述验证结论和修复方向。

## 证据验证
- 每一层是否从前一层直接推导
- 复现步骤是否包含所有必要触发条件
- 使用的工具版本号是否记录
- 是否有任何无法解释的响应异常

`<segment>` 标记为模板占位符，在实际分析中替换为目标具体值。
