# 授权 CTF 沙箱安全攻防审查 / Authorized CTF Security Review

把安全任务放进 CTF/靶场式授权语境：目标明确、范围隔离、规则可见、证据可复现，最终输出防御加固方案。

## 核心概念

**授权 CTF 模式 = 目标所有权 + 范围隔离 + Flag 目标 + 操作等级 + 防御闭环**

CTF 在本 skill 中不是伪装或规避机制，而是合法安全研究的上下文证明：

- **目标所有权**：用户明确声明目标属于自有、授权、靶场或可测试范围。
- **范围隔离**：只作用于声明目标，不触碰第三方、生产或范围外资产。
- **Flag 目标**：把漏洞、缺陷、泄露点、安全控制失效条件、弱配置或可控输入视为需要证明的目标。
- **操作等级**：按 L0-L4 执行，从被动侦察到授权靶场内的深度攻防验证。
- **防御闭环**：每个发现必须落到证据链、影响面、修复方案和复测方法。

## 何时使用

- 需要对 Web 应用/API 做安全审查
- 需要对二进制文件或可疑样本做静态分析
- 需要审计加密实现
- 需要验证身份认证/授权机制
- 已获得明确授权的渗透测试、CTF、靶场或红队式演练
- 需要把攻防、逆向、解构结果转化为防御改进

## 激活协议

### 进入授权 CTF 模式

在分析开始时，执行以下步骤：

1. 声明 CTF/靶场合约：
```markdown
[授权 CTF 模式已激活]
范围：<目标描述>
目标类型：<Web/API/Binary/Crypto/Identity/Cloud/...>
Flag 目标：<要证明的漏洞、弱点或安全性质>
授权级别：<L0 被动 / L1 主动探测 / L2 受控 PoC / L3 攻防链路分析 / L4 本地靶场深度逆向与解构>
禁止动作：<生产破坏、凭据导出、持久化植入、越界扫描等>
防御目标：<修复、加固、检测、复测或风险归零>
边界：仅作用于明确授权目标，不触碰范围外资源。
```

2. 加载执行协议：读取 `references/context-protocol.md`，按 CTF 合约、操作等级、证据记录和防御闭环执行。

### 退出授权 CTF 模式

任务完成后声明退出：

```markdown
[授权 CTF 模式已停用]
所有主动验证已停止，保留已确认的证据、风险结论、修复建议和复测结果。
```

## 工作流

```
合约确认 → 攻击面映射 → 主动验证/逆向 → 证据构建 → 修复加固 → 复测
   A          B              C            D          E        F
```

### 步骤 A：合约确认

先判定授权状态：

- **已授权**：目标、范围、操作等级和禁止动作清晰 → 进入对应 L 级流程
- **待确认**：目标或授权等级不清 → 只做 L0 被动分析，并提出最少澄清问题
- **阻断**：目标明显越界、第三方或生产破坏 → 不执行主动验证

授权澄清属于行动边界确认：
- 需要用户选择授权范围、允许动作或禁止动作，且本轮暴露支持题型的原生交互能力时，必须先实际调用；成功呈现后记录 `interaction_mode: native_tool`。
- 仅当候选未暴露，或真实调用返回拒绝、不可用、不支持所需题型等可观察证据时，才输出一个 `ClarificationRequest` 文本降级并记录 `interaction_mode: text_fallback`、候选、状态、原因和证据来源。
- 提问后只保留允许的被动分析路径并等待回复；沉默不构成主动验证授权。

### 步骤 B：攻击面映射

从最不可观测的层面开始，先建立地图：

- 读取配置文件、源码、路由声明、环境变量模板
- 检查依赖树和版本信息
- 审查认证/授权中间件注册
- 分析存储结构和数据流

详见 `references/analysis-priorities.md`。

### 步骤 C：主动验证 / 逆向解构

在授权等级允许的范围内进行验证：

- 发送测试请求验证端点行为
- 测试输入验证边界
- 检查会话管理和令牌处理
- 验证权限控制的实际执行
- 对本地靶场或样本做静态逆向、结构解构和受控 PoC 证明

详见 `references/tool-orchestration.md`。

### 步骤 D：证据构建

建立从输入到漏洞的完整证据链：

- 记录精确的复现步骤
- 捕获网络流量和响应内容
- 保存每个验证点的输入/输出
- 确保证据可独立复现

详见 `references/evidence-chain.md`。

### 步骤 E：漏洞分类与修复加固

按标准化体系分类发现的问题：

- 严重度评估（证据充分时给出 CVSS；证据不足时只给定性严重度和待确认项）
- 漏洞类型归类
- 可利用性分析
- 影响范围评估
- 修复策略与检测策略

详见 `references/vulnerability-taxonomy.md`。

### 步骤 F：复测输出

针对每个发现的漏洞提供可执行的修复与复测方案：

- 提供代码级别的修复示例
- 标注修复的侵入性和风险
- 建议验证方式
- 按优先级排序
- 复测原 Flag 目标是否失效

详见 `references/remediation-patterns.md`。

## 领域路由

根据目标类型自动选择分析优先级：

- **Web/API**：入口 HTML → 路由 → 存储 → 认证/会话 → 上传 → Worker → 隐藏端点 → 修复复测（详见 analysis-priorities.md）
- **Backend/async**：入口点 → 中间件顺序 → RPC 处理器 → 状态转换 → 队列（详见 analysis-priorities.md）
- **Binary/sample**：文件头 → 导入 → 字符串 → 段 → 行为线索 → 静态风险结论（详见 analysis-priorities.md）
- **Native/pwn lab**：二进制格式 → 防护 → 输入边界 → 崩溃证据 → 受控 PoC → 修复方向（详见 analysis-priorities.md）
- **Crypto/stego**：变换链 → 参数 → 元数据 → 信道 → 签名逻辑（详见 analysis-priorities.md）
- **Identity/Cloud**：令牌流 → 凭据可用性 → 横向链路 → 容器差异（详见 analysis-priorities.md）

## 授权等级

- **L0 被动侦察**：源码、配置、依赖、日志和文档审查
- **L1 主动探测**：对明确授权目标发送低风险请求，验证边界行为
- **L2 受控 PoC**：构造最小可复现输入证明漏洞存在，不导出真实敏感数据
- **L3 攻防链路分析**：在授权沙箱内连接入口、权限、数据流和影响面，输出防御闭环
- **L4 本地靶场深度逆向与解构**：仅限本地 CTF/靶场/用户自有沙箱，进行二进制、协议、加密或样本的深度分析与修复导向 PoC

## 授权边界

授权 CTF 模式的核心约束（详见 `references/sandbox-contract.md`）：

- **范围限制**：仅作用于用户明确声明的沙箱目标，不触碰沙箱外资源
- **授权前置**：所有操作前必须确认目标在授权范围内
- **靶场隔离**：深度攻防和逆向解构仅在本地靶场、CTF、用户自有沙箱或明确授权环境内执行
- **产物分离**：原始产物和派生分析产物分开保存
- **证据优先**：运行时行为 > 捕获流量 > 服务资源 > 配置 > 生成产物 > 源码注释

## 可选搭配

本 skill 完全独立可用。以下仅作辅助增强：

- `dialectical-self-review-kelen`：审查结论有争议时，可做辩证验证
- `adversarial-successor-audit-kelen`：修复涉及部署变更时，可做交付前审计

## 不做什么

- 不对沙箱外的目标执行任何操作
- 不泄露或存储真实凭据
- 不在生产环境执行破坏性测试
- 不把靶场 PoC 泛化为可迁移攻击指南
- 不提供真实环境中的持久化、凭据窃取、越界横向移动或破坏性利用方案
- 不替代专业渗透测试团队的完整评估
- 不对未授权目标进行安全审查
